# Book Chip Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every book screen names the open book in a top-bar chip, the same way in Personal and Family modes, and lets the user switch books in place. Screen titles go back to plain.

**Architecture:** One new widget file, `lib/widgets/book_chip.dart`: `BookChip` plus its "Which book?" bottom sheet. The chip reads `FamilyProvider` and `BookModeProvider` like `BookSwitch` does. It switches with the existing `openInBookWith`, then pushes the same named route on the root `navigatorKey`. The existing `BookSession` mode-change hook closes the old book's screens first (ruling R18). The list screens and Ko Toe Pwar chat put the chip first in their `AppBar.actions`. `bookTitle()` is deleted.

**Tech Stack:** Flutter (Provider), `flutter_test` widget tests.

**Spec:** `docs/superpowers/specs/2026-11-15-book-chip-design.md`

## Global Constraints

- Titles carry no family name in either mode.
- **The chip:**
  - shows `Icons.person_rounded` + "Personal" (existing `bookPersonal`), or `Icons.family_restroom_rounded` + the family name;
  - is followed by `Icons.expand_more_rounded`, or by `Icons.lock_rounded` while the family is read-only (in Family mode);
  - is never wider than 40% of the screen width; a long name ends in "…".
- **The sheet:**
  - title "Which book?" / "ဘယ်စာရင်းကို ကြည့်မလဲ";
  - two rows (Personal, the family's full name), a tick on the open one.
- **Picking a row:**
  - the other book: switch and reopen the same screen (route) in that book;
  - the open book: close the sheet only.
- No chip anywhere for someone not in a family, or where the family providers aren't in the tree.
- No chip on the dashboard, on detail/edit screens, or on the custom insight report screen. See the plan decision below.
- The other book's data must never show after a switch.
- No backend change. English and Myanmar strings for everything new.

**Plan decision (deviation from the spec, which listed "the custom insight report"):** `CustomInsightReportScreen` shows ONE saved report (`reportId`), so it is a detail screen. It gets a plain title and no chip, like the budget and goal detail screens. Reopening it in the other book would 404.

## Review Focus

1. **Double tap or a slow switch:** tapping a row while the sheet is closing, or tapping the chip twice. Expected: one switch and one pushed screen, with no crash or duplicate route. The test is in Task 1 (`one tap, one switch`).
2. **The family disappears while a screen is open** (left, removed or deleted, so `inFamily` becomes false). Expected: the chip disappears without an error. The test is in Task 1 (`chip goes away with the family`).
3. **Read-only family:** the chip shows a lock but stays tappable, because switching books is always allowed. Test in Task 1 (`read-only shows a lock and still switches`).
4. **Myanmar, 360 px, a very long family name:** the chip stays within 40% of the width and the screen's own action icons stay on screen. Test in Task 2 (`my 360 long name: chip and actions fit`).
5. **Transactions is opened with an unnamed `MaterialPageRoute` from the side menu.** Switching from it must still land on Transactions in the other book, via `/transactions`. Test in Task 2 (`switching from Transactions reopens Transactions`).
